# Start here: Pellier

Open **Workshop Studio → Getting started**, run its readiness checks, and keep the lab guide beside Code Editor. The environment is already prepared; the incomplete marked regions are the exercises.

| Code Editor group | Customer | What you build |
|---|---|---|
| [01 - Retrieve](labs/01-retrieve/README.md) | Anna | Ranking and a fallback that preserves her limits |
| [02 - Ground](labs/02-ground/README.md) | Marco | Stock facts and the agent’s tool grant |
| [03 - Deploy](labs/03-deploy/README.md) | Theo | A published, caller-bound tool on AgentCore |
| [04 - Govern](labs/04-govern/README.md) | Jessica and Nadia | Cedar authorization and PostgreSQL row ownership |

Each group has a short **README**, the **actual files to edit**, and a collapsed **solution** folder you can open if needed. The numbered files link to the application source; do not create a second implementation. Follow the guide’s marked edit regions.

**05 - Explore Pellier source** contains the full repository. Every prepared terminal starts there, so commands such as `python3 scripts/lab3_check.py` work whichever lab file is open.

If you opened the repository as a plain folder, choose **File → Open Workspace from File… → Pellier.code-workspace**. The same numbered folders are under `labs/`.

Work in order: observe the failure, predict, build, check, challenge, explain. Use each lab’s `solution/README.md` only when you choose recovery, then run the same checks. A copied answer or successful conversation does not count as proof.

At the end, follow the Summary to export your evidence before cleanup. For background, see [Repository and architecture](README.md) and the [Worksheet and check map](workshop/README.md).
